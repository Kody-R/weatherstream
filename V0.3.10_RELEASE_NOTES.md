# WeatherStream v0.3.10 — RWN Voice & Audio

This release adds a deterministic broadcast narration service around the existing
Weather Story Engine, ChannelWorker, Piper installation, and FFmpeg announcement
pipe. No LLM, cloud speech account, GPU, or new mandatory runtime package is added.

## Architecture

`Weather snapshot → Story → NarrationPlanner → WeatherSpeechFormatter → Script →
TtsProvider → AudioCache → RwnAudioDirector → ProgramAudioMixer → FFmpeg/HLS`

The supervisor prepares each channel's scripts when its weather/configuration
revision changes, including idle on-demand channels. Generation runs off the video
thread. Ordinary synthesis has one worker and a bounded queue; official warning
synthesis has a separate worker so forecast jobs cannot queue ahead of warnings.
The old Local on the 8s phase clock and measured-duration handshake remain in use.

The director owns playback, rundown concept memory, desk changes, interruptions,
caption text, and Studio state. The four logical mixer buses are Alert, Voice,
Stinger, and Bed. Alert audio wins over all other sources. Generated PCM is
normalized before caching; the final FFmpeg output has a limiter. Software,
VAAPI, QSV, and NVENC command selection remains unchanged.

## Configuration and upgrade

Schema **27 → 28** adds the `audio` section. Existing channels, regions, maps,
observations, event desks, Story configuration, schedules, Studio rundowns,
motion, encoders, branding, and legacy `tts`/`music` settings are retained.
Voice stays disabled on upgrades unless legacy TTS was already enabled. Such
installations migrate to Local on the 8s (or Severe Only when local narration was
disabled), preserving provider voice, volume, speed, and severe preference.

The new **RWN Voice & Audio** panel in Settings is authoritative for broadcast
narration. The older Piper panel remains for voice download/test and compatibility.
Use `config/settings.example.json` for all defaults. Existing persistent `/config`
volumes migrate automatically. Back up the volume before replacing an installation.

Modes:

- **Off:** no generated broadcast narration; existing non-voice alert chimes remain.
- **Minimal:** station/story introductions and changed NWS/event summaries.
- **Local on the 8s:** local blocks plus enabled official severe interruptions.
- **Full Weathercast:** eligible data-backed slides, plus local blocks and warnings.
- **Severe Only:** only qualifying official takeover alerts activate voice.

Each high-value screen can be disabled independently. Missing/unsupported facts
produce silence, not inferred conditions. Radar images and tropical track geometry
are not interpreted as meteorological facts. Tropical overview narration uses
actual NHC system name, wind, and movement fields.

Logical Broadcast, Local, News, and Severe profiles are configured under
`audio.profiles`; provider voice, speed, and volume are supported by Piper.
Additional style/pitch/pause metadata can be retained for future adapters; Piper
currently ignores unsupported parameters. `audio.desk_profiles` maps desks to
profiles. The provider interface exposes synthesis, health, and available voices.

## Provider setup and storage

Use the existing Admin Piper voice download control, or place a matching `.onnx`
model and `.onnx.json` config in `/config/tts/voices`. The existing Docker image
already installs `piper-tts==1.7.0`. Voice assets are not bundled in this ZIP.
Network access is needed only if downloading a model; installed models work locally.

New audio uses `/config/audio` so the existing CasaOS/Docker volume persists it.
`WEATHERSTREAM_AUDIO` can override that root. Directories are `station`,
`generated`, `alerts`, `stingers`, `beds`, and `cache`. PCM and metadata live in
`cache`; transient provider output goes in `generated`. Cache keys include script,
provider, and resolved voice parameters. Metadata includes duration, generation,
expiration, channel, weather/config revision, hashes, and profile. Identical speech
is deduplicated across channels. Defaults are six-hour expiry and 128 cache entries.
Corrupt clips are skipped; generation failures back off for 60 seconds.

## Timing, priority, and severe weather

Scripts first fit an estimated word budget, then use measured PCM duration.
Overlong ordinary scripts lose complete trailing sentences and are regenerated.
The renderer's shared timeline can extend a slide by 0, 2, 3 (default), or 5 seconds.
A clip that still cannot fit is skipped. Late clips do not start just to be cut off.
Ordinary rundown changes hold an admitted clip's graphic until speech completes;
manual takeovers and official severe events can interrupt immediately.

Warnings use structured NWS hazard, area, expiration, and verbatim instruction
language. No invented shelter advice or freeform rewriting is applied. Official
warning scripts cannot be manually edited. A new/updated warning clears ordinary
audio. A ready warning does not wait for a decorative sounder. Alert audio bypasses
ordinary voice mute. Video hard-cut behavior continues through the existing severe
takeover system; pending ordinary speech is discarded. Local 8 and manual
takeovers are aborted before warning playback.

An uncached warning still needs synthesis time. Video switches immediately while
audio generates; this release cannot promise zero-latency speech. Oversized warning
audio beyond the three-minute cache safety bound is rejected rather than truncated.

## Music and original RWN sounds

Background beds are optional and disabled by default. Put user-owned audio under
`/config/audio/beds`, select its filename, then choose Local Forecast, Full
Weathercast, or Station ID mode. Files are decoded/normalized in the background;
up to the first two minutes are looped with fades to bound memory. The default bed
level is -24 dB, ducking to -34 dB while speech plays. Bed failure does not stop voice.
Legacy music remains available when the new Background Mode is None; Studio's
Mute Live Bed controls the new bed bus, not the separate legacy music input.
Switching between legacy music and the new bed input requires a channel restart.

Original 0.9-second pentatonic Station, Update, Severe, Local, and Tropical assets
are in `app/static/audio`. These are branding plucks, not EAS/SAME sounds. Station, update, tropical, Local on the 8s, and severe sounders have automatic
hooks. Ordinary stingers are omitted if they would prevent voice from fitting. No copyrighted background music is included.
To replace an automatically used sounder, place `station.wav`, `update.wav`, `local.wav`, `tropical.wav`, or `severe.wav` in
`/config/audio/stingers` (stereo PCM, 44.1 kHz, 16-bit, at most two seconds), then
restart the channel/service to clear the in-memory asset.

## Studio and captions

The Audio panel reports provider, profile, mode, current/next slide, duration,
cache/queue, generation time, errors, and voice/bed state. Operators can preview,
stop browser preview, regenerate, test voice, clear expired clips, mute live voice
or bed, edit a segment, and reset it to automatic. Preview endpoints return WAV to
the browser and never enqueue live playback. Mutations use existing Admin auth.
Overrides are channel/slide scoped and runtime-only; they never modify weather
data and do not survive a service restart. Save Edit affects future admissions,
not PCM already playing. Unchanged Minimal NWS/event summaries are suppressed.

Caption modes are Off, Narration, Severe Only, and Always. Captions use short
estimated four-second pages above the existing data ribbon. They are not forced
word alignment or a separate subtitle track. Always retains the current segment's
last caption page until the segment changes. The official footer/banner stays clear.
