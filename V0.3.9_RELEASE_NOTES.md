# WeatherStream v0.3.9 — Studio Control Room 2.0

v0.3.9 is an operations release. It does not replace the v0.3.8 Broadcast Motion or v0.3.7 Event Channel Identity systems; it adds the control surface needed to see and safely operate the automated network.

## Production Monitor

Studio now shows two broadcast monitors: **LIVE** is sourced from the channel worker preview when the encoder is running and falls back to a generated renderer preview when an on-demand channel is idle. **NEXT** is generated from the renderer's actual next timeline item. The monitor also shows slide progress, remaining time, channel lifecycle state, realtime/encoder state, active daypart, and playout source.

## Live Rundown

The active renderer sequence is displayed independently from the persistent rundown editor. Each row has a thumbnail, duration, and LIVE/NEXT/QUEUED state. Repeated slides are tracked by timeline index rather than name so severe sequences containing repeated `alert_radar` items remain accurate. Local on the 8s and operator takeovers are treated as out-of-band blocks and show the automatic sequence that will resume next.

## Weather Story Inspector

Studio surfaces the current Weather Story title, score, reason, supporting signals, NOW/NEXT/LATER/CONTEXT sections, whether the Story Engine is directing or monitoring, and whether Studio, severe takeover, or a specialty channel is overriding normal automatic direction. The existing **Load Story Into Editor** action remains available.

## Source Health

WeatherStream normalizes existing source telemetry into operational states: `HEALTHY`, `CACHED`, `STALE`, `ERROR`, `WAITING`, and `DISABLED`. Source-specific freshness windows are used for fast-changing products such as radar/alerts versus slower products such as climate normals. Error text and age since last successful refresh are visible in Studio.

## Operator Takeover

An operator can TAKE LIVE any registered Studio slide for 30 seconds, 60 seconds, 2 minutes, 5 minutes, or 15 minutes. This starts an idle on-demand channel if necessary, preempts a Local-on-the-8s block, and automatically returns to the underlying automatic timeline when the hold expires. Takeovers are **runtime-only** and are never restored after a WeatherStream restart.

Official qualifying severe-weather takeovers always have priority. Studio refuses a new operator takeover while official severe coverage is active, and if severe coverage begins during an operator takeover the manual hold is immediately cleared.

## Safe Areas and Operations Trail

The LIVE/NEXT monitors include optional title-safe and action-safe guides for television/overscan checks. Studio also shows recent in-memory lifecycle, refresh, Studio, and recovery events from WeatherStream observability. Control Room preferences are saved separately from rundown publishing.

## Compatibility

Settings advance to **Schema 27**. Existing v0.3.8 channel configuration, Event Channel Identity, Broadcast Motion, Story Engine, maps, observations, icons, TTS, encoder settings, published Studio sequences, schedules, and bumpers are preserved. Any development-era persisted `manual_takeovers` field is discarded during migration because v0.3.9 takeovers are runtime-only by design.

## Validation

The release is covered by the complete regression suite plus dedicated tests for Schema 27 migration, source-health classification, runtime-only manual takeover behavior, severe-weather takeover protection, and Studio Control Room surfaces. Python compilation, inline Studio JavaScript syntax, Docker Compose parsing, API route integrity, and browser visual QA are also validated before packaging.
